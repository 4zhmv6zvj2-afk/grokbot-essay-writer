Update install
An installed app updates in place from GitHub. Run essay-writer --check-update; it names the current version, the newest release, and whether an update is available. When one is, run essay-writer --update. It asks the GitHub release API, and if that API is blocked it reads the public releases feed. It downloads the release source archive and SHA256SUMS, verifies the SHA-256, and does not check the Sigstore signature. It installs the hash-pinned runtime dependencies and the new package into the existing environment, then runs essay.health. If the requirements install succeeds and a later step fails, the result says the environment changed and was not rolled back. The update does not touch /workspace/Essay-writer: the setup record, the stored keys, the remembered Mac folder, and the essays stay. It does not re-run essay.setup, the four-way card, or the sign-in card. Start a new session after the update so the host launches the new code, then run essay-writer --health and confirm the new version and that it is alive. A git checkout updates with git pull; --update refuses a source checkout and says so. Pass --force to replace a source checkout with the release package. A copy that has no --update command yet updates once through the download and first_run.py above. If the GitHub download is unavailable, the same release can be installed offline from a zip with essay-writer --install-upload /path/to/the.zip.

A normal git clone of the public repo is for developers. A friend install downloads the GitHub release.

Fake-IP DNS
If this computer's proxy resolves external names to 198.18.0.0/15, set ESSAY_WRITER_TRUSTED_EGRESS to a subnet of that range, in the environment or the setup secrets file. One invalid token disables the setting. A proxy that uses another range, such as 10.0.0.0/8 or 100.64.0.0/10, is not supported: turn that routing off, or use the standard fake-IP range. Leave the setting empty on every other computer.

File work defaults to Cursor. On this computer, when agent is missing, setup downloads nothing and reports reason cursor-install-needs-consent. Ask the person before installing the Cursor CLI. With their yes, rerun setup with --install-cursor (or ESSAY_WRITER_ALLOW_CURSOR_INSTALL=1). That consent authorises the download only: setup downloads the installer to a file, reports its SHA-256, byte count, and path, does not run it, and reports reason cursor-install-needs-hash. Show the SHA-256 and ask. To run that exact file, rerun setup with --cursor-sha256 <the reported SHA-256> (or set ESSAY_WRITER_CURSOR_INSTALL_SHA256=<the reported SHA-256>). A hash that does not match reports cursor-install-hash-mismatch and runs nothing. A match runs the downloaded file with a fixed argv and reports the hash. The hash confirms which bytes were downloaded, not that the vendor is trustworthy: when you cannot check it against a trusted channel, install the Cursor CLI manually with the command below instead. Setup never pipes a remote script into a shell.

The Cursor CLI installer is an unsigned remote script. Run it only on a computer you control and only when this setup asks. To install it yourself, run:

curl -fsS https://cursor.com/install -o cursor-agent-install.sh
shasum -a 256 cursor-agent-install.sh  # Linux: sha256sum cursor-agent-install.sh
bash cursor-agent-install.sh

For a manual install of the app itself, clone the public repo and run `uv sync --extra dev`; the chat-driven install is optional.

Show this card: "Open Consensus → API keys → New key → paste once on the secret card. Ask Free or Pro."

Ordinary setup collects the Consensus key, the Consensus plan, the Unpaywall email, and the OpenAlex key on the setup secret card, then passes them to essay.setup.

The Consensus key is for academic research search: it finds papers for the research step. Consensus's help center says the API is how a tool programmatically searches academic research and retrieves relevant papers: https://help.consensus.app/en/articles/16516328-the-consensus-api

Create that key with Consensus's own steps from that page. Click the profile icon in the bottom-left corner, select API & MCP Dashboard, open the Keys and Clients tab, click New key, give the key a name so you can tell what it is for, then create it and copy it somewhere secure. The full key is shown once. If it is lost, revoke it and create a new one. The same path is on https://docs.consensus.app/api-plans-and-access : profile icon, then API & MCP Dashboard, then Keys and clients, then New key. The dashboard named from get-started is https://consensus.app/api-mcp

Ask which Consensus plan they have. Free stores ESSAY_WRITER_CONSENSUS_PAID as 0. Pro stores it as 1. Teams, Deep, and Enterprise use 1, the same paid flag as Pro. Do not add another flag. The published limits are only those on https://docs.consensus.app/api-plans-and-access : Free includes 30 calls a month and the maximum with additional usage is 30; Pro includes 500 and the maximum with additional usage is 1,000. Max papers per request is 20 on Free and 300 on Pro. Pagination past the first page is no on Free and yes on Pro. Full-text excerpts are no on Free and yes on Pro. The rate limit is 1 request per second on Free and 1 request per second on Pro.

The email is for Unpaywall free-PDF lookup only. Unpaywall's API docs say a request must include the email as ?email=YOUR_EMAIL, and they ask for at most 100,000 calls a day: https://unpaywall.org/products/api . That email does not change OpenAlex limits. OpenAlex ignores mailto, and the polite pool was retired in February 2026: https://help.openalex.org/api/deprecations/ . Do not invent an email address. Do not say that Unpaywall's own page promised never to email.

The OpenAlex key raises the free look-up budget. OpenAlex's authentication page says to make an account at openalex.org, then copy the key from Settings → API key: https://help.openalex.org/api/authentication/ . The settings page is https://openalex.org/settings/api . A free key includes $1 of usage per day. Calls with no key share $0.10 per day on that network address, and OpenAlex can rate-limit them: https://help.openalex.org/access/pricing/ . Pass that key to essay.setup as openalex_api_key.

If the user skips the Consensus key, the Unpaywall email, the OpenAlex key, or any of them, show the warning before the skip is accepted. Consensus is not used when the key is missing. Unpaywall free PDF lookup will not run when the email is missing. OpenAlex still runs without a key, on a small daily budget shared with everyone on the same network address, and that budget can be rate-limited. A free OpenAlex key raises that budget. After an explicit yes to that warning, call essay.setup with confirmPhase draft, acknowledge_skipped_searches true, and the same other arguments. Show that result. After another explicit yes, call essay.setup with confirmPhase confirm and those same arguments. A confirm that skips without acknowledge_skipped_searches writes nothing.

Do not ask the user to edit a .env file. Do not repeat the key, the email, or the OpenAlex key.
